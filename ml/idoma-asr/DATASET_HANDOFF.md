# Idoma ASR dataset handoff\n\nThe Idoma ASR training pipeline only consumes samples that have passed the application review/validation process and have been explicitly marked `asr_eligible=true`.\n\n## Required flow\n\n1. Collect Idoma audio and its native transcript.\n2. Store the sample in the Bible Arena voice-review workflow.\n3. Complete the required speaker/native-language review.\n4. Mark the sample ASR eligible only after validation.\n5. Export the eligible rows to JSONL.\n6. Run `scripts/export_asr_manifests.py` to create training, validation, and evaluation manifests.\n7. Keep the held-out evaluation split untouched during training.\n8. Run `scripts/prepare_ctc_features.py` to produce the CTC-ready datasets.\n9. Run `scripts/train_ctc.py` without `--execute` first.\n10. Train only after the dry run and ML environment checks pass.\n\n## Manifest contract\n\nEach source row must contain: `id`, `storage_path`, `language_code` (`id`), `native_transcript`, `dataset_split`, and `asr_eligible` (`true`).\n\nThe exporter writes only: `id`, `audio`, `nativeTranscript`, and `language_code`.\n\nAudio files are referenced by path; the manifest does not contain audio bytes.\n\n## Current state\n\nAs of the latest verified database check, Bible Arena has zero Idoma audio uploads, zero Idoma voice-language samples, and zero ASR-eligible Idoma samples. Therefore no training run is authorized yet.\n\nThis is intentional: the project must never manufacture a model, transcript, dataset count, WER, or CER result.
